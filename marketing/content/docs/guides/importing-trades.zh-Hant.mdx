在側邊欄打開**導入**（快捷鍵 `G` `I`）。流程是**上傳 → 列映射 → 結果** ——
選擇賬戶、拖入文件、確認映射、導入完成。文件只在你的服務器上解析，不會發送給任何第三方。

不知道怎麼從券商導出文件？導入頁面的 **Find my broker**（或 `/connect`）會打開券商目錄 ——
選中你的券商後，導入頁面會針對所選賬戶顯示該券商的導出步驟。

## 支持的格式

格式根據文件的表頭自動識別。[支持的券商](/zh-Hant/docs/guides/supported-brokers)的導出文件會
自動填好列映射和時區；其他券商的成交導出只要完成列映射就能導入：

| 格式 | 說明 | 需要映射？ |
|--------|------------|---------------|
| **成交 CSV** | 每行一筆成交 —— 多數券商對賬單導出的形式 | 需要（[支持的券商](/zh-Hant/docs/guides/supported-brokers)自動填好） |
| **MetaTrader 對賬單** | MT5 *交易歷史報告*（XLSX/HTML）或 MT4 *對賬單*（HTML），原樣上傳 —— 見[支持的券商](/zh-Hant/docs/guides/supported-brokers) | 不需要 |
| **日誌導出** | 每行一筆完整交易，含開平倉（Stonk Journal 風格：`Date, Symbol, Side, Qty, Entry, Exit, …, Tags, Setup, Notes`）。每行生成一筆完整交易及日誌批註 | 不需要 |
| **JSON 備份** | TraderMemos 的[導出文件](/zh-Hant/docs/self-hosting/backup-restore) —— 恢復成交、策略手冊、現金流水與賬戶元數據 | 不需要 |

## 列映射（成交 CSV）

每個標準字段映射到你 CSV 中的某一列，或選擇**（跳過）**。常見表頭會自動建議：

| 字段 | 必填 | 可自動識別的表頭示例 |
|-------|----------|--------------------------------|
| `symbol` | ✔ | Symbol、Ticker、Instrument |
| `side` | ✔ | Side、B/S、Action（`buy`/`b`/`bot`、`sell`/`s`/`sld`） |
| `quantity` | ✔ | Qty、Quantity、Shares、Contracts |
| `price` | ✔ | Fill Price、Price、Avg Price、Exec Price |
| `executed_at` | ✔ | Trade Date、Date/Time、Datetime |
| `fees` / `commission` | — | Fee(s) / Commission、Comm |
| `instrument_type` | — | Market、Asset Type、Sec Type |
| `option_right` | — | Call/Put、Option Type、Right |

時間戳支持 ISO 8601（`2026-07-01T15:04:05Z`）、`2026-07-01 15:04:05`、
`07/01/2026 15:04:05` 以及純日期 —— 全部以 UTC 時刻存儲。

- **時區** —— 不帶偏移量的時間按文件的時區讀取：券商預設的時區；其他成交 CSV 則使用**市場時區**
  （默認美東 —— 大多數導出都是）。如果你的券商用其他時區導出，請在映射步驟中修改。
- **日期次序** —— `05/01/2026` 這類斜線日期既可讀作 5 月 1 日，也可讀作 1 月 5 日。若有儲存格
  能確定次序（如 `13/01/2026`），預覽只會回顯讀取結果；若所有日期兩種讀法都成立，會出現一個
  沒有默認值的**日期次序**選擇器（每個選項都寫明示例日期的讀法），選定前無法導入。
- **示例行**按實際導入結果顯示：每個已映射欄位一列（下方註明讀取的文件列），每個時間後附上
  轉換後的時刻（`→ Oct 1, 6:08:13 AM EDT`），沒有被讀取的文件列會變暗並標為 *not imported*。期權成交會帶上看漲 / 看跌方向
（顯式列或從代碼推斷）與 ×100 的乘數。

## 去重與重複導入

一筆成交的唯一性由**代碼 + 方向 + 數量 + 價格 + 時間戳**共同決定，按賬戶隔離。同一份
對賬單導兩次、或日期範圍重疊，重複部分只會計入**已跳過（重複）**。重複導入永遠是安全的。

*同一文件內*完全相同的成交（代碼、方向、數量、價格、時間精確到秒都相同 —— 例如券商拆分了一筆
訂單）都會保留：每次出現都有帶序號的獨立標識，所以再次導入同一文件時它們仍會全部被跳過。

## 成交如何歸組爲交易

每次導入後賬戶會自動重新歸組：同一代碼 / 品種的成交按時間順序遍歷 —— 同向成交加倉、
反向成交減倉，倉位歸零時交易平倉（跨越零點的成交會開啓下一筆交易，其手續費按數量在兩筆交易間分攤）。日誌批註掛在交易上，
重新歸組後依然保留。

導錯了？每次導入與 Flex 同步都是一個批次 —— **設置 → 賬戶 → 同步與匯入紀錄**列出全部批次
（賬戶頁面只列該賬戶的），**回滾**會移除該批次的成交並重新歸組。沒有成交的定時 Flex 同步默認
隱藏，點擊 **Show empty syncs** 才顯示。

## 限制

上傳大小由 `TM_IMPORT_MAX_BYTES` 限制（默認 **10 MiB**，約數萬行）。自託管用戶可以調高
—— 參見[配置參考](/zh-Hant/docs/self-hosting/configuration) —— 同時保持代理的請求體限制
高於它。超大的歷史記錄可按年份拆分；去重機制讓文件重疊不會造成問題。

## 其他導入途徑

- **IBKR Flex 同步** —— 通過 IBKR Flex Query 定時自動導入，在 `/connect` 或賬戶頁面的
  **Interactive Brokers · Flex sync** 卡片中設置（間隔由 `TM_JOB_FLEX_SYNC_INTERVAL_MIN` 控制）
- **截圖掃描** —— 用 LLM 從券商截圖提取成交，參見 [AI 功能](/zh-Hant/docs/guides/ai-features)
- **手動錄入** —— **新建交易**抽屜（快捷鍵 `c` `t`）
- **API / 腳本** —— 攜帶[個人訪問令牌](/zh-Hant/docs/guides/api-tokens)調用
  `POST /api/v1/executions`；同樣的去重規則適用
- **CLI** —— 在 API 容器內執行 `tradermemos import --account … --file …`
