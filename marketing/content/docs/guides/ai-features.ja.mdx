どちらの AI 機能も**既定では無効**で、完全に任意です。TraderMemos はこれらがなくても問題なく
動作します。両機能は **OpenAI 互換**の `chat/completions` エンドポイントであれば何でも利用でき
ます。OpenAI、OpenRouter、Azure OpenAI、あるいは Ollama / LM Studio のようなローカルサーバーも
使えます。キーはご自身で用意してください。

設定はどちらも**設定 → AI** から行います。最初に押さえておきたい点が 2 つあります。

- 設定は**サーバー全体**に適用されます（ユーザーごとではなく、インスタンスごとに 1 つの構成です）。
- API キーはサーバー上にのみ保存され、保存後にブラウザから見えるのはマスクされたヒントだけです。

## スクリーンショットスキャン（約定の抽出）

証券会社アプリのスクリーンショットから約定を抽出し、入力し直す手間をなくします。**新規トレード**
ドロワーの**スキャンで入力**は、1 枚以上の PNG / JPEG / WebP のスクリーンショット、または CSV /
JSON の約定ファイルを受け取り、フォームに反映する前にレビュー画面へ並べます。

- ファイルごとに行が表示され、モデルが読み取る間の進捗がわかります。
- すべて完了すると、銘柄ごとのカードに約定、平均エントリー／エグジット、FIFO の純損益が表示
  されます（複数銘柄のスクリーンショットにも対応）。
- フォームが変わるのは**フォームに入力**を押したときだけです。何も読み取れなかった場合は代わりに
  **閉じる**が表示され、モデルのメモが理由として残ります。

細かい処理はサーバーが担います。約定時刻はスクリーンショットに表示されたタイムゾーン（時刻の横の
`美東` などのラベル）、なければマーケットタイムゾーンで読み取り、年が省略されていても未来の日付に
ならないように補います。取消・拒否・未約定の注文はスキップされ、ロング／ショートは約定そのもの
から判定します。プロバイダーが過負荷のときはサーバーが 2 回再試行し、それでも駄目なら
**503 `ocr_busy`**（再試行を促すメッセージ付き）を返します。

**設定 → AI → スクリーンショットスキャン**での設定項目:

| 項目 | 備考 |
|-------|-------|
| 有効化 | 機能をオンにします |
| API ベース URL | 例: `https://api.openai.com/v1`、`https://openrouter.ai/api/v1`、`http://localhost:11434/v1` |
| モデル | **画像入力（vision）**に対応している必要があります — 既定は `gpt-4o-mini`。**モデルを取得**でエンドポイントが提供するモデルを一覧できます |
| API キー | 後から編集する際に空欄のままにすると、現在のキーが維持されます |
| カスタムプロンプト | 任意 — 空欄の場合は組み込みの約定抽出プロンプトが使われます |

保存前に**テスト**で接続を確認してください。画像は 10 MiB（`TM_OCR_MAX_BYTES`）に制限され、
リクエストは 90 秒（`TM_OCR_VISION_TIMEOUT_SEC`）でタイムアウトします。低速なローカルモデルでは
より長いタイムアウトが必要になる場合があり、
[リバースプロキシ](/ja/docs/self-hosting/reverse-proxy)は 120 秒以上を許可する必要があります。

## トレードコーチ

任意のトレードの詳細画面で**AIに聞く**を押すと、トレードの情報（約定、損益、R 倍率、MAE/MFE、
セットアップ、感情、タグ、あなたのメモ）に加え、**エントリー時点での状態** — その日・その週の
それまでの損益、連勝・連敗、ドローダウン、直近の決済に付けた感情 — がモデルに送られます。
返ってくるレビューの内容:

- **コーチングの所見** — モデルが書くそばから 1 件ずつストリーミング表示されます。
- **次のアクション** — 次のトレードで確認できる具体的な指示を 1 つ。
- トレードごとの**執行スコア** — エントリー、エグジット、リスク、テンポをレポートと同じ 0〜100
  のスケールで。

レビューは保存されます。トレードを開き直すと前回のレビューが表示され、ボタンは**再生成**に
変わります。コーチが無効な場合や到達できない場合は、組み込みのルールベースの所見にフォール
バックします。

**設定 → AI → トレードコーチ**での設定項目は上記と同じです（画像入力は不要で、どのチャット
モデルでも動作します）。加えて、コーチングのスタイルを変えるための任意の**システムプロンプト**が
あります。

モバイルでは、モデルの行を押すとベンダーごとにまとめられた検索可能なピッカーシートが開きます。
スクリーンショットスキャンでは画像を読めないモデルが *Show all models* の奥に隠され、エンドポイントが
提示しないモデル ID も直接入力できます。

## 環境変数によるヘッドレスな既定値

スクリプト化されたデプロイでは、`TM_OCR_*` / `TM_COACH_*` 変数で両機能をあらかじめ設定できます。
[設定](/ja/docs/self-hosting/configuration)を参照してください。環境変数の値はあくまで既定値と
して働き、UI で設定を保存した後はデータベースの値が優先されます。

## プライバシー

トレードデータとスクリーンショットは、あなたが設定したエンドポイント**のみ**に送信されます。
ローカルモデルに向ければ、データがマシンの外に出ることはありません。
