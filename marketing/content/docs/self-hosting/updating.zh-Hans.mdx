数据库迁移在 **API 启动时自动执行** —— 升级就是拉取 + 重启。不过大版本跳跃前仍建议先
[备份](/zh-Hans/docs/self-hosting/backup-restore)。

## Docker（默认方式）

```bash
cd TraderMemos
git pull                     # 获取 compose / Makefile 的变更（如有）
docker compose pull          # 拉取新版镜像
make up                      # 重建容器（docker compose up -d）
```

如果你是从源码构建而非拉取 Hub 镜像：

```bash
git pull
make up-build                # 从仓库重新构建两个镜像
```

验证运行中的版本：

```bash
curl -s http://localhost:3000/healthz
# {"status":"ok","version":"0.15.0","go":"go1.27.0","commit":"…"}
```

## 锁定版本（生产环境推荐）

`latest` 会随每次发版变动。在根目录 `.env` 中锁定版本，并有意识地手动升级：

```bash
# .env
TM_IMAGE_TAG=0.15.0
```

```bash
# 升级：修改 TM_IMAGE_TAG，然后
docker compose pull && make up
```

已发布的标签遵循语义化版本：`0.15.0`、`0.15`、`0`、`latest`，以及不可变的 commit `sha` 标签。
镜像为多架构（`amd64` + `arm64`）。版本与变更记录见
[CHANGELOG](https://github.com/sinhong2011/TraderMemos/blob/main/CHANGELOG.md) 与
[GitHub Releases](https://github.com/sinhong2011/TraderMemos/releases)。

## 迁移的行为

- 迁移脚本内嵌在 API 二进制中，启动时自动应用（SQLite 与 Postgres 各有一条迁移链）。
- SQLite 数据库旁的文件锁（`tradermemos.db.migrate.lock`）可防止两个进程同时执行迁移。
- **不支持自动降级**。schema 迁移完成后回退到旧版镜像是不受支持的 —— 请改用
  [升级前的备份](/zh-Hans/docs/self-hosting/backup-restore)进行恢复。

## 自定义 trading-system schema（一次性）

一份草稿版 trading-system 地图构建，在官方 0.16.1 把 `mcp_settings` 发布为 SQLite 50 /
Postgres 14 之前，就把功能迁移占用了这些编号（SQLite 50–52、Postgres 14–16）。
因此官方 0.16.1 会在这些数据库上拒绝启动（`no migration found for version 52`）。

当前官方编号为：

- SQLite 50 `mcp_settings`、51 `trading_system`、52 `system_plans`、53 `system_plan_evidence`
- Postgres 14 `mcp_settings`、15–17 为同一条功能链

启动时，如果 API 发现 trading-system 表已存在、缺少 `mcp_settings`，且
`schema_migrations` 仍停留在旧的自定义版本（SQLite 50–52 或 Postgres 14–16），
就会先应用 `mcp_settings`，按已有表写入对应的官方版本号，再继续执行剩余迁移。
已有的 trading-system、计划、证据和周复盘行会保留。MCP 在所有者主动开启前保持关闭。
升级前仍需先做[备份](/zh-Hans/docs/self-hosting/backup-restore)。

如果 `schema_migrations` 显示这些版本，但数据库既不符合自定义历史、也不符合官方链，
启动会报错退出，而不会改写版本号。

## Fork / CDN 部署

- **Vercel / Cloudflare / Netlify 的 Web**：推送到 fork 默认分支即自动重新部署；把 fork
  与上游同步就完成了更新。
- **Railway 的 API**：推送即重新部署。`/data` 数据卷跨部署持久保留 —— 保持挂载即可。
