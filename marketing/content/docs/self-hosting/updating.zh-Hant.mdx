數據庫遷移在 **API 啓動時自動執行** —— 升級就是拉取 + 重啓。不過大版本跳躍前仍建議先
[備份](/zh-Hant/docs/self-hosting/backup-restore)。

## Docker（默認方式）

```bash
cd TraderMemos
git pull                     # 獲取 compose / Makefile 的變更（如有）
docker compose pull          # 拉取新版鏡像
make up                      # 重建容器（docker compose up -d）
```

如果你是從源碼構建而非拉取 Hub 鏡像：

```bash
git pull
make up-build                # 從倉庫重新構建兩個鏡像
```

驗證運行中的版本：

```bash
curl -s http://localhost:3000/healthz
# {"status":"ok","version":"0.15.0","go":"go1.27.0","commit":"…"}
```

## 鎖定版本（生產環境推薦）

`latest` 會隨每次發版變動。在根目錄 `.env` 中鎖定版本，並有意識地手動升級：

```bash
# .env
TM_IMAGE_TAG=0.15.0
```

```bash
# 升級：修改 TM_IMAGE_TAG，然後
docker compose pull && make up
```

已發佈的標籤遵循語義化版本：`0.15.0`、`0.15`、`0`、`latest`，以及不可變的 commit `sha` 標籤。
鏡像爲多架構（`amd64` + `arm64`）。版本與變更記錄見
[CHANGELOG](https://github.com/sinhong2011/TraderMemos/blob/main/CHANGELOG.md) 與
[GitHub Releases](https://github.com/sinhong2011/TraderMemos/releases)。

## 遷移的行爲

- 遷移腳本內嵌在 API 二進制中，啓動時自動應用（SQLite 與 Postgres 各有一條遷移鏈）。
- SQLite 數據庫旁的文件鎖（`tradermemos.db.migrate.lock`）可防止兩個進程同時執行遷移。
- **不支持自動降級**。schema 遷移完成後回退到舊版鏡像是不受支持的 —— 請改用
  [升級前的備份](/zh-Hant/docs/self-hosting/backup-restore)進行恢復。

## 自訂 trading-system schema（一次性）

一份草稿版 trading-system 地圖構建，在官方 0.16.1 把 `mcp_settings` 發布為 SQLite 50 /
Postgres 14 之前，就把功能遷移占用了這些編號（SQLite 50–52、Postgres 14–16）。
因此官方 0.16.1 會在這些資料庫上拒絕啟動（`no migration found for version 52`）。

目前官方編號為：

- SQLite 50 `mcp_settings`、51 `trading_system`、52 `system_plans`、53 `system_plan_evidence`
- Postgres 14 `mcp_settings`、15–17 為同一條功能鏈

啟動時，如果 API 發現 trading-system 表已存在、缺少 `mcp_settings`，且
`schema_migrations` 仍停留在舊的自訂版本（SQLite 50–52 或 Postgres 14–16），
就會先套用 `mcp_settings`，依既有資料表寫入對應的官方版本號，再繼續執行剩餘遷移。
既有的 trading-system、計劃、證據和週回顧列會保留。MCP 在擁有者主動開啟前保持關閉。
升級前仍需先做[備份](/zh-Hant/docs/self-hosting/backup-restore)。

如果 `schema_migrations` 顯示這些版本，但資料庫既不符合自訂歷史、也不符合官方鏈，
啟動會報錯退出，而不會改寫版本號。

## Fork / CDN 部署

- **Vercel / Cloudflare / Netlify 的 Web**：推送到 fork 默認分支即自動重新部署；把 fork
  與上游同步就完成了更新。
- **Railway 的 API**：推送即重新部署。`/data` 數據卷跨部署持久保留 —— 保持掛載即可。
